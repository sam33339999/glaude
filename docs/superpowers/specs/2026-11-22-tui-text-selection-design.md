# TUI 內建文字選取與複製（短版）

日期：2026-11-22 ｜ 規模：中小改動

## 意圖

TUI 開了滑鼠回報（`MouseModeCellMotion`，為了滾輪捲動），終端機原生選取被吃掉，只能靠 Option／Fn／Shift+拖曳繞過。使用者只是要**複製畫面上的東西**：一段程式碼片段，或一個不認識的生字。要在 TUI 內直接拖曳選取、放開即複製，滾輪捲動照舊。

## 目標 / 非目標 / 反目標

- 目標：在訊息區拖曳反白、放開複製到系統剪貼簿；雙擊選一個字；複製出的程式碼能直接貼上用（無行尾空白、無多餘縮排）。
- 非目標：選取輸入框、狀態列、對話框、協調面板；對回原始 markdown（折行處不接回）；鍵盤選取模式；整塊程式碼一鍵複製（日後若長行斷開成為痛點再做，見做法 C）。
- 反目標：滾輪捲動壞掉；Ctrl+C 中斷語意被改；一般點擊／打字行為改變；修飾鍵+拖曳的原生選取失效。

## 做法

| 做法 | 取捨 | 結果 |
|---|---|---|
| A. 依畫面格子選取＋清理（去行尾空白、共同縮排） | 改動集中 TUI 層；超寬折行的程式碼複製出來會斷行 | **採用**（使用者選定） |
| B. 反查原始 markdown | 折行不斷；glamour 無行對應表，工程量數倍且表格/清單易錯位 | 不採用 |
| C. A ＋點程式碼區塊複製整塊原文 | 解決長行斷開；需追蹤區塊在畫面的位置 | 延後 |

## 設計

**座標**：只處理訊息 viewport 的列。viewport 頂端列 = 協調面板的行數；內容行 = `viewport.YOffset + (y − vpTop)`，欄 = 終端格（cell）。選取的錨點與游標都存**內容座標**（行、欄），所以拖曳中滾輪捲動、串流追加新行都不會讓選取錯位。

**事件**（bubbletea v2，滑鼠模式維持 CellMotion）：
- `MouseClickMsg` 左鍵：在訊息區內 → 設錨點，清掉舊選取；在區外 → 清掉選取，其餘行為不變。
- `MouseMotionMsg`（左鍵按住）：更新游標；拖到 viewport 上緣／下緣之外 → 每個 motion 事件捲 1 行並把游標夾在邊緣。
- `MouseReleaseMsg`：選取非空 → 複製；錨點＝游標（單純點擊）→ 不複製、無選取。
- 雙擊（兩次 click 間隔 ≤ 400ms 且同一格）：選取該格所在的「字」——連續的英數字與 `_`，或連續的 CJK 字元；選到即複製。
- `Esc`、終端機寬度改變 → 清掉選取。複製後選取保留顯示，直到下一次點擊／Esc。

**反白**：`View()` 在 viewport 輸出後，對落在選取範圍的可見行，以 `x/ansi` 切格：選取段落去色後套 reverse 樣式，前後未選段保留原樣式。寬字元（CJK）端點對齊到字元邊界。

**取字**：對選取範圍每行做 `ansi.Strip` ＋依欄切段 → 去行尾空白 → 去掉所有非空行的共同開頭空白 → 以 `\n` 串接。全空則不複製。

**寫入剪貼簿**（兩路都送）：
1. `tea.SetClipboard`（OSC 52）——SSH 遠端時可用。
2. 本機原生寫入：`internal/clipboard` 新增 `WriteText`——darwin `pbcopy`、linux `wl-copy`（Wayland）或 `xclip -selection clipboard`，其他平台略過。原因：macOS Terminal.app 不支援 OSC 52、iTerm2 預設關閉。
   原生寫入失敗且無法確定 OSC 52 生效時，不報錯（OSC 52 可能已成功）；成功時以既有一次性提示機制顯示 `Copied N characters`。

**測試**：取字（行尾空白、共同縮排、CJK 寬字元切段）、座標換算（含協調面板偏移、捲動後）、事件流程（拖曳／點擊／雙擊／Esc／區外點擊）以假的 clipboard writer 驗證寫入內容、`WriteText` 各平台指令選擇。

## 留給實作者

- 雙擊判定的時間窗與「字」的字元類別細節可微調。
- 反白樣式用 reverse 或主題色背景皆可，以兩種主題下都清楚為準。

## Cache-first

純 TUI 顯示與本機剪貼簿，不動 prompt、工具、請求。
